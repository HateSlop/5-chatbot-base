# 코드 구조와 확장 지점

## 현재 동작

```text
브라우저 ── GET /, /detail, /chat ──> app.py ──> templates + config
브라우저 ── POST /api/chat ────────> app.py ──> ChatbotService
   ↑              JSON 응답 {reply,image,sources}          │
   └───────────────────────────────────────────────────────┘
```

`app.py`는 입력을 검증하고 화면과 JSON 응답을 담당합니다. `services/chatbot_service.py`는 현재 **고정된 데모 문구**를 돌려줍니다. 검색, 모델 API, 대화 상태는 아직 연결되어 있지 않습니다. `GET /health`는 서버의 단순 생존 확인입니다.

이 구조는 **작동 예시**입니다. 기획에 맞춰 템플릿·CSS·JS를 전부 바꾸거나, 프런트를 별도 프로젝트로 옮기거나, Flask와 API 형식을 바꿔도 됩니다. 아래 표는 현재 파일의 책임을 설명하며 제출할 파일 구조를 지정하지 않습니다.

| 위치 | 역할 |
| --- | --- |
| `config/chatbot_config.json` | 이름, 설명, 태그, 대표 이미지 경로, 첫 인사 |
| `templates/` | Flask/Jinja 화면 3개 |
| `public/assets/` | CSS, 브라우저 JavaScript, 예시 SVG 이미지 |
| `services/chatbot_service.py` | 팀의 답변 생성 구현 지점 |
| `data/knowledge/` | 직접 준비할 원본 자료의 위치 예시 |
| `tests/` | 현재 데모와 API 계약의 기본 확인 |

`public/`은 Flask의 정적 폴더이면서, Vercel에서 정적 파일을 배치할 때 쓰는 이름입니다. 템플릿은 Flask가 렌더링합니다. 브라우저 코드는 `/api/chat`에 상대 경로로 요청하므로 화면과 API가 같은 도메인일 때 바로 동작합니다. 분리 배포를 선택한다면 프런트의 API 주소와 교차 출처 정책을 바꾸세요.

## 답변 서비스 계약

현재 화면과 API를 유지할 때 `ChatbotService.generate_response(user_message, username)`는 다음 딕셔너리를 반환합니다.

```python
{
    "reply": "사용자에게 보여줄 답변",
    "image": None,         # 또는 브라우저가 접근 가능한 이미지 URL
    "sources": [],         # 실제 답변에 활용한 자료 이름
}
```

`app.py`가 자료형을 검사해 JSON으로 내보냅니다. 모델이 자유 형식으로 출력한 값을 검증 없이 그대로 반환하지 마세요. 출처 목록은 **실제로 검색·사용한 자료**에만 채우세요. 인용 위치나 링크가 필요하면 API 계약과 화면을 함께 확장하세요.

프런트와 서버를 분리하거나 스트리밍·다중 캐릭터 등 다른 대화 경험을 만든다면 이 계약을 바꿀 수 있습니다. 변경한 요청·응답 형식은 프런트와 서버 담당자가 함께 합의하고 팀 README에 적으세요.

## 자료 기반 답변으로 확장

```text
원본 자료 → 정리·분할 → 검색 인덱스 생성 → 사용자 질문
                                      ↓
                          관련 자료 검색·선별
                                      ↓
                      캐릭터 설정 + 자료 + 질문 → 답변
                                      ↓
                            근거·오류·품질 확인
```

인덱스 생성은 요청마다 반복하지 않는 편이 좋습니다. 로컬 ChromaDB를 실험에 쓴다면 원본 자료와 생성된 인덱스의 경로를 분리하고, 배포 환경에서 인덱스를 어디에 보관할지 결정하세요. 서버리스 파일시스템을 영구 저장소로 가정하지 마세요. 저장소, 모델, 프롬프트 설계는 기획에 맞게 바꿀 수 있습니다.

## 입력과 실패 처리

빈 입력·잘못된 JSON은 `400`, 2,000자를 넘는 메시지는 `413`, 서비스 내부 오류는 `500`입니다. 현재 브라우저는 오류 메시지를 대화창에 표시합니다. 실제 모델을 연결한 뒤에는 API 키 누락, 공급자 제한, 검색 결과 없음, 응답 지연도 다루세요. 로그에 API 키나 사용자 대화 전문을 남길지 신중히 결정하세요.
