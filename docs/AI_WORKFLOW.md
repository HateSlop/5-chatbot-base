# AI 도구를 활용한 작업

에디터·대화형 AI·코드 생성 도구는 팀이 자유롭게 선택합니다. 특정 도구의 설정 파일이나 프롬프트가 과제의 필수 조건은 아닙니다.

1. 구현을 부탁하기 전에 **현재 동작, 바꾸려는 동작, 재현 방법**을 짧게 적으세요.
2. 생성된 코드는 실제 파일과 의존성 버전에 맞는지 확인하고 실행하세요. 존재하지 않는 함수나 오래된 배포 안내가 섞일 수 있습니다.
3. API 키·개인정보·공개 권한이 없는 자료를 프롬프트, 커밋, 이슈에 붙이지 마세요.
4. 기능을 하나 연결할 때마다 로컬에서 성공·오류 경로를 확인하고, 최종적으로 공개 URL에서 다시 확인하세요.
5. 팀 README에는 AI가 쓴 문구보다 **팀이 선택한 설계 이유와 확인한 결과**를 남기세요.

복잡한 변경에서는 작은 단계로 나누면 리뷰하기 쉽습니다. 예를 들어 “자료 읽기 → 검색 결과 반환 → 답변에 반영 → 출처 표시 → 실패 처리” 순서로 확인할 수 있습니다.
