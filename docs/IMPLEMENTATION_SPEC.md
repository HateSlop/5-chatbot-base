## 적용한 결정: 플레이 종료와 새 시작

플레이 중 사용자가 화면을 떠났다가 돌아와 이어하는 경우는 이번 시연 범위에서 제외했습니다. 게임 화면을 벗어나거나 새로고침한 뒤 다시 시작하면 이름 입력 화면부터 보여 주고 새 플레이 기록을 만듭니다. 이전 플레이의 대화, 호감도, 단서는 새 플레이에 섞이지 않습니다.

엔딩은 먼저 읽을 수 있게 보여 줍니다. 엔딩 뒤 **새 이름으로 다시 시작**을 누르면 이름을 다시 입력받습니다. 같은 이름을 입력해도 새 플레이가 시작됩니다. 새로고침·화면 이탈 뒤 재진입·엔딩 뒤 새 시작은 로컬 화면에서 확인했습니다.

## 이 문서를 갱신하는 규칙

기능을 구현하거나 고칠 때마다 **같은 변경 작업에서 이 표도 갱신**합니다. 무엇이 실제로 되는지, 무엇을 시험했는지, 무엇이 남았는지를 개발 용어 없이 씁니다. 확인하지 않은 동작은 완료로 표시하지 않습니다. 공개 배포 상태는 실제 주소에서 확인한 뒤에만 바꿉니다. 상세 기술 내용이 필요하면 [API 계약](API_CONTRACT.md)이나 관련 코드·검사에 기록합니다.

## 후속 수정: 실제 채팅 연결과 화면 표현

- **담당 yejoon, 로컬 연결 확인:** 위에서 발견한 실제 게임 시작 오류를 고쳤다. 표지의 굵은 `START`는 `/chat`으로 이동한다. 집 배경과 3초 뒤 지미의 이름 질문은 세션 생성 전의 화면 연출이며, 기존의 작은 이름 모달에서 확인하면 실제 `/api/session`을 호출한다. 이름을 프런트에만 가짜로 등록하지 않고 서버 응답으로 플레이를 시작한다. 서버의 첫 인사는 현재 기존 문구이며, 도입 TV 장면은 계속 독립 미리보기다.
- **전송 동작:** 클릭과 Enter가 같은 전송 경로를 사용한다. Shift+Enter는 줄바꿈이고, 한글 조합 중 Enter는 전송하지 않는다. 현재 대화 상대·서버 진행 토큰·입력 글을 `/api/chat`에 보낸다. 실패하면 글과 토큰을 유지해 다시 시도할 수 있다. 사건 진행과 호감도 계산은 기존 서버가 계속 담당한다.
- **화면 표현:** 배경을 읽은 뒤 대사창과 채팅 입력창을 표시한다. 오래 걸린 이전 장면의 그림이 새 장면을 덮지 않게 했다. 정육점은 스테이크 모양 아이콘을 사용한다. 대사창은 짙은 반투명 패널·얇은 금색 테두리·짧은 등장 효과로 정리했으며, 움직임 줄이기 설정에서는 등장 효과를 끈다. 기록은 접어서 볼 수 있게 유지하고 행동 선택지는 현재 대사창 안에 놓았다.
- **직접 확인:** 로컬 브라우저에서 이름 확인 후 새 세션 응답 201, 실제 화면의 호감도 50 표시, Enter/버튼의 `/api/chat` 도달을 확인했다. 로컬 환경에는 AI API 키와 고정 진행 키가 없었다. 파일을 바꾸지 않는 임시 진행 키로 세션을 검증했으며, AI 키 누락으로 대화 응답은 500 오류였다. 따라서 실제 AI 답변 성공으로 표시하지 않는다. 팀장은 실행 환경의 `OPENAI_API_KEY`와 `STORY_STATE_KEY`를 설정한 뒤 답변과 재시도를 확인해야 한다.
- **남은 일:** 이름 질문/인사 내용을 서버 사건 대사와 통일하는 작업은 팀장·프로듀서와 협의한다. 현재 진행 중인 병합의 스테이징은 유지했고 병합 완료·커밋·push는 하지 않았다. 공개 배포와 세 결말의 실제 브라우저 완주는 이번 작업에서 확인하지 않았다.
- **자동 검사:** 배경 표시 순서·오래된 이미지 응답 무시·Enter/한글 조합·전송 실패 후 재시도 등을 포함한 화면 검사 28개와 서버 검사 19개가 통과했다. 이 검사는 실제 AI API 키가 필요한 모델 응답 성공을 뜻하지 않는다.
