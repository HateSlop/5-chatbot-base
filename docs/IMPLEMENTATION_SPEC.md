## 지금 어디까지 왔나요?

이름을 입력하고 마을 사람들과 대화하며 사건을 따라가 세 결말 중 하나에 도달하는 첫 버전이 만들어졌습니다. 이번 로컬 작업에서 시작 버튼을 실제 이름 입력 화면에 연결하고, 이름을 입력하면 같은 화면에서 새 플레이가 바로 열리도록 고쳤습니다. 이어하기 버튼과 브라우저 저장 기록을 통한 복원을 없앴습니다. 현재 장면의 사건 대사와 대화 상대의 대화만 보이도록 화면 기록도 정리했습니다. 로컬 브라우저에서 첫 이동과 캐런의 실제 AI 답변, 새로고침 및 뒤로 가기 뒤 이름 입력 화면 복귀를 확인했습니다. 서버 검사 19개와 화면 검사 18개를 통과했습니다. [공개 주소](https://chatbot-bb1234.onrender.com/)에는 이 변경을 확인하지 않았습니다.

## 누가 무엇을 맡나요?

- 팀장 `suyoung`: 이야기 규칙, 인물 대사와 공개 정보, 진행 기록, 서버, Render 설정과 배포.
- 팀원 `yejoon`: 화면, 그림 연결, 모바일 표시와 화면 검사.
- 프로듀서: 최종 그림을 전달하고, 공개 주소에서 대화와 이야기 흐름을 시험해 의견을 남김.
- 함께 결정: 이야기 내용은 [스토리](STORY.md), 화면과 서버가 주고받는 정보는 [API 계약](API_CONTRACT.md)을 먼저 고침. `README.md`, `AGENTS.md`, `docs/`, `requirements.txt`는 공유 문서·파일임.

각 개발자는 자기 브랜치에서 작업하고 `main`으로 검토 요청을 보냅니다. 팀장이 확인한 뒤 합칩니다. 첫 통합 버전은 이미 `main`에 포함되어 있습니다.

## 다음 순서

1. 팀장과 팀원이 이번 변경을 함께 검토하고 `main`에 합친 뒤, 공개 주소에서 새로 시작·장면 대화·장소·호감도 표시를 다시 확인합니다. 로컬 브라우저에서도 세 결말 뒤 새 시작과 좁은 화면을 추가 확인합니다.
2. 팀장과 프로듀서가 실제 AI로 사건 직후의 질문, 인사 반복 여부, 네 인물의 대화 이어짐과 낮은 호감도에서의 말투 변화를 시험합니다. 대화 분류와 +3/-3점, 12회 제한이 실제 플레이에 적절한지도 조정해야 합니다. 현재 기억은 인물당 최근 대화 10번 분량이며, 오래된 대화까지 계속 기억하는지는 별도 설계가 필요합니다.
3. 팀원과 프로듀서가 최종 그림을 연결하고 모바일 화면과 답변별 그림을 확인합니다. 프로듀서가 [시연 안내](PRODUCER_TEST_GUIDE.md)를 따라 세 결말을 시험합니다.

## 적용한 결정: 플레이 종료와 새 시작

플레이 중 사용자가 화면을 떠났다가 돌아와 이어하는 경우는 이번 시연 범위에서 제외했습니다. 게임 화면을 벗어나거나 새로고침한 뒤 다시 시작하면 이름 입력 화면부터 보여 주고 새 플레이 기록을 만듭니다. 이전 플레이의 대화, 호감도, 단서는 새 플레이에 섞이지 않습니다.

엔딩은 먼저 읽을 수 있게 보여 줍니다. 엔딩 뒤 **새 이름으로 다시 시작**을 누르면 이름을 다시 입력받습니다. 같은 이름을 입력해도 새 플레이가 시작됩니다. 새로고침·화면 이탈 뒤 재진입·엔딩 뒤 새 시작은 로컬 화면에서 확인했습니다.
