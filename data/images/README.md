# 대화용 이미지 자료

실제 이미지 파일은 브라우저에서 열 수 있는 `public/assets/images/` 또는 팀이 선택한 이미지 저장소에 둡니다. 이 폴더에는 이미지별 장면 설명·출처·사용 권한 같은 메타데이터와 임베딩을 만드는 자료를 둘 수 있습니다. 현재는 예시 자료나 인덱스가 없으며 이미지는 자동 선택되지 않습니다.

처음에는 이미지마다 ID와 장면 설명을 붙이고, 상황과 이미지의 간단한 대응 규칙으로 출력할 이미지와 생략할 경우를 정해 보세요. 예를 들어 “인사 장면”, “비 오는 장면”, “특정 장소”처럼 확인 가능한 상황으로 시작합니다. 여러 질문을 넣어 이미지가 어울리는 때에만 표시되는지 확인합니다.

그다음 최종 결과에 필요한 임베딩 유사도 기반 이미지 선택을 구현합니다. 답변 문장과 실제 이미지 내용을 직접 비교하려면 둘을 같은 벡터 공간에 놓는 이미지·텍스트 임베딩 모델이 필요합니다. CLIP 계열 모델을 쓰면 이미지와 문장을 비교 가능한 벡터로 만들 수 있습니다. 이미지 벡터는 미리 만들어 이미지 ID·URL·설명과 함께 저장하고, 생성된 답변 문장 벡터로 가까운 후보를 찾습니다. 유사도가 기준에 못 미치면 이미지를 보내지 않습니다.

OpenAI의 기본 임베딩 API는 텍스트를 입력으로 받습니다. 이 API를 사용한다면 이미지 파일 자체 대신 이미지의 장면 설명을 임베딩하고, 답변 문장과 비교합니다. 이것은 설명문을 통한 의미 검색이며 실제 이미지 내용에서 만든 임베딩과 직접 비교하는 방식은 아닙니다. 이미지와 문장을 직접 비교하는 선택지로 [OpenAI CLIP](https://github.com/openai/CLIP) 같은 이미지·텍스트 모델을 사용할 수 있습니다. 이미지 벡터는 인덱스를 준비할 때 한 번 만들어 두고, 채팅 요청에서는 답변 문장 벡터만 만들어 검색합니다. 운영진이 제공하는 OpenAI 키는 이 모델 파일이나 실행 환경을 대신하지 않습니다. 이미지 설명 방식과 이미지 자체 임베딩 방식 중 무엇을 구현했는지 문서에 구분해 적으세요. [OpenAI 임베딩 API 입력 형식](https://developers.openai.com/api/reference/resources/embeddings/methods/create)

임베딩 모델은 벡터를 만들고, ChromaDB는 벡터와 메타데이터를 저장하고 가까운 후보를 검색하는 도구입니다. 작은 후보 목록에서는 직접 유사도를 계산할 수도 있습니다. ChromaDB가 이미지를 이해하거나 임베딩을 생성하는 것은 아닙니다. 감정 분류 모델은 이미지·문장 임베딩 검색과 다른 선택 방법이며, 필요성이 확인되면 별도로 더할 수 있습니다. `services/image_selector.py`가 선택된 URL을 반환하는 구현 자리입니다.

이미지 임베딩과 인덱스는 채팅 요청마다 새로 만들지 말고 미리 준비하세요. 배포 환경에서 인덱스를 읽을 수 있는지 확인합니다. API 키나 공개 권한이 없는 자료는 이 폴더를 포함해 Git에 올리지 마세요.
