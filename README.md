# 더뉴빌리지로 오세요

1955년 미국의 수상한 마을로 이사 온 플레이어가 주민과 대화하고 물건을 조사하며 진실에 다가가는 스토리 챗봇입니다. 선택과 마을 전체의 호감도에 따라 **탈출·사망·동화** 중 하나의 결말을 맞습니다.

**공개 시연:** [더뉴빌리지로 오세요](https://5-chatbot-base.vercel.app/) · Vercel 배포. Render 무료 서비스의 전송량 한도 소진 후 이전했습니다. 팀이 공개 화면에서 전체 플레이를 시연하고 동작을 확인했습니다.

게임에서 사용하는 시작 배경, 수상한 방, 축제 음식 그림입니다. 실제 플레이에서는 장소 그림 위에 캐릭터와 대화창이 나타나고, 왼쪽에 주인공 정보와 추천 질문이 표시됩니다.

## 주요 기능과 서비스 흐름

1. 시작 화면에서 주인공을 선택하고 이사 장면을 본 뒤 이름을 입력합니다. 왼쪽에는 주인공 사진·이름·1955년의 이야기 날짜·직업·마을 호감도가 보입니다.
2. 1일차부터 6일차까지 주민과 자유롭게 대화하고 추천 질문을 참고하며 장소를 이동합니다. 정육점 지갑, 캐런의 액자, 축제 음식을 눌러 조사합니다. 이야기가 하루 넘어갈 때 왼쪽 날짜도 바뀝니다.
3. 서버가 장면 이동·조사 결과·호감도와 차 키를 판정합니다. 귀가 시 호감도가 65점 미만이면 정육점 사망 경로로, 65점 이상이면 일자리와 축제 경로로 갑니다. 축제에서는 선택과 제한 시간에 따라 결말이 갈립니다.
4. 게임 화면을 새로고침하거나 떠나면 플레이 기록이 종료됩니다. 결말 뒤 다시 시작해도 성별 선택과 이름 입력부터 진행합니다.

### AI 대화와 이미지 출력

자유 대화는 현재 **한 인물**과만 합니다. 서버는 그 인물의 성격·말투, 현재 장면의 공개 사건, 그 인물과 나눈 최근 대화, 지금 알려져도 되는 마을 정보를 AI에 전달합니다. 질문에 맞는 정보는 `data/knowledge/facts.json`에서 **인물·장면·획득 단서로 먼저 제한한 뒤 키워드로 찾습니다.** 사건의 순서·단서·결말은 AI가 아닌 서버 규칙이 판정합니다.

자유 입력마다 AI가 플레이어 발화를 먼저 분류하고, 서버가 호감도를 갱신한 뒤, AI가 갱신된 태도에 맞는 답변과 표정 단서를 만듭니다. `services/image_selector.py`는 이 단서와 장면 규칙으로 `data/images/catalog.json`의 인물 이미지를 고릅니다. 선택한 이미지는 다음 대사나 장면 전환까지 유지합니다. 이미지 선택에 임베딩 유사도 계산은 사용하지 않습니다.

### 호감도

호감도는 50점에서 시작하며 모든 주민이 같은 수치를 공유합니다. AI가 플레이어의 말을 **호의·협조·중립·적대**로 분류하고, 서버가 각각 기본 **+5·+7·0·−2점**을 적용합니다. 호감도 상승 폭은 점수가 높아질수록 줄고, 적대가 이어지면 감점은 **−2→−4→−6점**으로 커집니다. 같은 문장의 반복과 같은 장면에서의 중복 채점은 막습니다. 미용실 도움·발각·직업 선택 같은 사건은 고정 점수를 적용하며, 사진 사건 뒤 **65점**을 기준으로 이후 경로가 갈립니다. 자세한 계산은 [호감도 규칙](docs/AFFINITY_RULES.md)에 있습니다.

## 아키텍처와 데이터 흐름

```text
브라우저(HTML·CSS·JavaScript)
  ├─ 선택·조사 → Flask /api/action → story.py가 장면·단서·호감도·결말 판정
  └─ 자유 대화 → Flask /api/chat
                 → facts.json에서 공개 정보 검색
                 → OpenAI가 발화 분류 → 서버가 호감도 갱신
                 → OpenAI가 인물 대사·표정 단서 생성
                 → catalog.json에서 인물 이미지 선택
  ← 장면(view)·대사(events)·암호화된 진행 토큰
```

진행 토큰은 플레이 중인 브라우저 화면의 메모리에만 두며 `STORY_STATE_KEY`로 암호화합니다. 캐릭터별 최근 대화 10번도 이 토큰에 포함됩니다. 서버에는 플레이어별 기록을 영구 저장하지 않습니다. 화면은 서버가 보낸 장면과 사건을 표시하며 엔딩을 다시 판정하지 않습니다. API 필드와 오류 응답은 [API 계약](docs/API_CONTRACT.md)을 따릅니다.

## 기술 스택과 선택 이유

| 기술 | 쓰는 곳과 이유 |
| --- | --- |
| Python·Flask | 장면 규칙과 대화 API를 한 서비스에서 운영 |
| HTML·CSS·JavaScript | 장소 배경, 인물, 채팅, 조사·선택, 날짜와 호감도 화면을 동적으로 표시 |
| OpenAI Responses API | 발화 분류와 인물의 자유 대사·표정 단서를 생성 |
| JSON 파일과 키워드 검색 | 공개 가능한 사실과 소수의 이미지 목록을 관리하며 공개 범위를 확인하기 쉬움 |
| 암호화된 진행 토큰 | 로그인이나 영구 저장 없이 한 번의 플레이를 이어 가고 재시작하면 기록을 버림 |
| Vercel Hobby | 공개 URL로 시연하고 이미지·영상·음악은 정적 파일로 제공 |

**DB와 임베딩을 도입하지 않은 이유:** 마을 정보와 이미지 후보가 적고 고정되어 있어 JSON 파일과 공개 범위별 키워드 검색으로 필요한 정보를 찾을 수 있습니다. 플레이 기록도 화면을 떠나면 폐기하므로 영구 저장용 DB가 필요하지 않습니다. 이미지 역시 인물·장면·표정 단서로 후보를 명확히 고를 수 있어 임베딩 유사도 비교를 사용하지 않았습니다. DB 없이 임베딩을 구현하는 것은 가능하며, 이미지와 정보가 늘어나 검색 품질이 떨어지면 도입을 다시 검토할 수 있습니다.

## 실행 및 테스트

```powershell
conda activate chatbot-base
python -m pip install -r requirements.txt
python app.py
```

프로젝트 루트의 `.env`에 `OPENAI_API_KEY`와 `STORY_STATE_KEY`를 설정하고 `http://localhost:5000`을 엽니다. `.env.example`에는 공개 가능한 변수 이름과 기본값만 있습니다. 실제 키는 Git에 올리지 않습니다. `STORY_STATE_KEY`용 Fernet 키는 다음 명령으로 만듭니다.

```powershell
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

```powershell
python -m unittest discover -s tests -v
node --test tests/*.test.cjs
```

서버 검사는 장면 분기·호감도·비밀 공개 범위·세 결말·오류 처리를, 화면 검사는 대화·조사·선택·이미지·엔딩 연출을 다룹니다. 팀은 Vercel 공개 화면에서 전체 플레이를 시연했습니다. 시연 순서는 [프로듀서 안내](docs/PRODUCER_TEST_GUIDE.md)에 정리했습니다.

## 개발 중 문제와 해결

| 겪은 문제 | 적용한 해결 |
| --- | --- |
| 고정 사건 대사와 자유 대화가 따로 놀아 직전 상황에 엉뚱하게 답함 | 이미 공개된 사건 대사와 관찰 상황을 AI 입력에 연결하고 비공개 단서는 장면·단서 조건으로 제한 |
| 이전 플레이가 테스트에 겹침 | 화면을 벗어나거나 엔딩 뒤 새 시작할 때 진행 토큰을 버리고 처음부터 시작 |
| 대화 중 표정이 현재 상황과 어긋남 | 답변 생성 전 호감도를 갱신하고 표정 단서와 장면 규칙으로 인물 이미지를 고름 |
| Vercel에서 일부 캐릭터 이미지 주소가 비어 장면에 인물이 빠짐 | 등록된 이미지 주소를 서버의 파일 위치와 관계없이 반환하고, 배포 전 실제 파일을 검사 |
| 액자를 바꿔 볼 때 이전 사진이 잠깐 보이거나 The End 글자가 먼저 나타남 | 새 이미지가 준비될 때까지 액자를 숨기고, 엔딩 글씨는 쓰기 시작 전 마스크로 가림 |
| 공개 환경에서 웹페이지 형태의 오류가 응답되어 채팅이 깨짐 | 화면에 재시도 안내를 보이고 질문을 남겨 다시 보낼 수 있게 처리 |

## 개선 결과와 검증 방법

장면의 공개 사실을 AI 입력에 연결해 지미의 행선지, 캐런의 수색 요청, 사진 조사에 관한 질문을 현재 사건에 맞춰 처리합니다. 호감도와 엔딩은 서버 검사로, 이미지 전환과 대사 순서는 화면 검사로 검증합니다. Vercel 공개 화면에서도 전체 플레이를 시연해 이야기와 화면 연결을 확인했습니다.

## 알려진 제한과 다음 개선점

- **이미지 검색:** 답변·이미지 임베딩 유사도 대신 인물별 표정 단서와 장면 규칙을 사용합니다. 후보가 많아지면 이미지 설명문과 답변의 임베딩을 비교하는 방식을 검토할 수 있습니다.
- **대화 기억:** 캐릭터별 최근 10번의 대화를 한 플레이 동안 기억합니다. 새 플레이에는 이전 대화가 이어지지 않습니다.
- **대기 시간:** 영상·음악 전송과 AI 응답에는 네트워크 상태에 따른 대기가 생길 수 있습니다. 개선 방향은 [최적화 문서](docs/OPTIMIZATION.md)에 정리했습니다.

## 회고와 협업

사건·단서·결말을 서버 규칙에 두고 자유 대사를 AI에 맡겨 대화의 유연성과 이야기의 순서를 함께 유지했습니다. 규모가 작은 고정 자료에는 JSON과 키워드 검색이 운영하기 쉬웠습니다. 캐릭터의 말투와 공개 사실을 장면마다 제한하는 일이 몰입감에 가장 큰 영향을 주었습니다.
