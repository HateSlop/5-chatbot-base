# 더뉴빌리지로 오세요

1955년 미국의 수상한 마을로 이사 온 플레이어가 주민과 대화하고 물건을 조사하며 진실에 다가가는 스토리 챗봇입니다. 선택과 마을 전체의 호감도에 따라 **탈출·사망·동화** 중 하나의 결말을 맞습니다.

**공개 시연:** [더뉴빌리지로 오세요](https://5-chatbot-base.vercel.app/) · Vercel Hobby 배포. Render 무료 서비스의 전송량 한도 소진 후 이 주소로 옮겼습니다. 2026-11-10 공개 주소에서 첫 화면·광고 영상, 서버 상태, 남성 주인공의 새 플레이, 지미와의 실제 AI 대화 및 호감도 변화를 확인했습니다. 여성 경로·세 결말·모바일 화면·30명 동시 접속은 아직 확인하지 않았습니다.

## 주요 기능과 서비스 흐름

1. 시작 화면에서 성별을 고르고 이사 장면을 본 뒤 이름을 입력합니다. 왼쪽에는 주인공 사진·이름·오늘 날짜·직업·마을 호감도가 보입니다.
2. 1일차부터 6일차까지 주민과 자유롭게 대화하고 추천 질문을 참고하며 장소를 이동합니다. 정육점 지갑, 캐런의 액자, 축제 음식을 눌러 조사합니다. 이야기가 하루 넘어갈 때 왼쪽 날짜도 바뀝니다.
3. 서버가 장면 이동·조사 결과·호감도와 차 키를 판정합니다. 귀가 시 호감도가 65점 미만이면 정육점 사망 경로로, 65점 이상이면 일자리와 축제 경로로 갑니다. 축제에서는 선택과 제한 시간에 따라 결말이 갈립니다.
4. 게임 화면을 새로고침하거나 떠나면 플레이 기록이 종료됩니다. 결말 뒤 다시 시작해도 성별 선택과 이름 입력부터 진행합니다.

### AI 대화와 이미지 출력

자유 대화는 현재 **한 인물**과만 합니다. 서버는 그 인물의 성격·말투, 현재 장면의 공개 사건, 그 인물과 나눈 최근 대화, 지금 알려져도 되는 마을 정보를 AI에 전달합니다. 질문에 맞는 정보는 `data/knowledge/facts.json`에서 **인물·장면·획득 단서로 먼저 제한한 뒤 키워드로 찾습니다.** 사건의 순서·단서·결말은 AI가 아닌 서버 규칙이 판정합니다.

자유 입력마다 AI가 플레이어 발화를 먼저 분류하고, 서버가 호감도를 갱신한 뒤, AI가 갱신된 태도에 맞는 답변과 표정 단서를 만듭니다. `services/image_selector.py`는 이 단서와 일부 장면 규칙으로 `data/images/catalog.json`의 실제 인물 이미지를 고릅니다. 답변마다 표정이 달라질 수 있지만, 현재 **답변 문장과 이미지 설명의 임베딩 유사도를 계산하지는 않습니다.**

### 호감도

호감도는 50점에서 시작하며 모든 주민이 같은 수치를 공유합니다. 자연스러운 인사·감사·관심은 기본 +5점, 실제 도움은 기본 +7점이며, 점수가 높을수록 실제 상승 폭이 줄어듭니다. 위협·모욕이나 지속적인 압박은 처음 −2점, 연속되면 −4점·−6점으로 커집니다. 같은 말의 반복은 다시 채점하지 않고, 중요한 사건 행동에는 별도의 고정 점수를 적용합니다. 자세한 판정은 [호감도 규칙](docs/AFFINITY_RULES.md)에 있습니다.

## 아키텍처와 데이터 흐름

```text
브라우저(HTML·CSS·JavaScript)
  ├─ 선택·조사 → Flask /api/action → story.py가 장면·단서·호감도·결말 판정
  └─ 자유 대화 → Flask /api/chat
                 → facts.json에서 공개 정보 검색
                 → OpenAI가 발화 분류 → 서버가 호감도 갱신
                 → OpenAI가 인물 대사·표정 단서 생성
                 → catalog.json에서 인물 이미지 선택
  ← 장면(view)·대사(events)·암호화된 진행 토큰
```

진행 토큰은 플레이 중인 브라우저 화면의 메모리에만 두며 `STORY_STATE_KEY`로 암호화합니다. 캐릭터별 최근 대화 10번도 이 토큰에 포함됩니다. 서버에는 플레이어별 기록을 영구 저장하지 않습니다. 화면은 서버가 보낸 장면과 사건을 표시하며 엔딩을 다시 판정하지 않습니다. API 필드와 오류 응답은 [API 계약](docs/API_CONTRACT.md)을 따릅니다.

## 기술 스택과 선택 이유

| 기술 | 쓰는 곳과 이유 |
| --- | --- |
| Python·Flask | 장면 규칙과 대화 API를 한 서비스에서 운영하고 Vercel에 배포. Gunicorn은 다른 Linux 실행 환경에서 사용 가능 |
| HTML·CSS·JavaScript | 장소 배경, 인물, 채팅, 조사·선택, 날짜와 호감도 화면을 동적으로 표시 |
| OpenAI Responses API | 발화 분류와 인물의 자유 대사를 생성하고 구조화된 결과를 받음 |
| JSON 파일과 키워드 검색 | 공개 가능한 사실과 소수의 이미지 목록을 관리하며 공개 범위를 확인하기 쉬움 |
| 암호화된 진행 토큰 | 로그인이나 영구 저장 없이 한 번의 플레이를 이어 가고 재시작하면 기록을 버림 |
| Vercel Hobby | 공개 URL로 시연하고 이미지·영상·음악은 정적 파일로 제공 |

**DB를 두지 않은 이유:** 현재 마을 정보와 이미지 목록은 작은 고정 자료이고, 플레이 기록은 화면을 떠나면 삭제하는 기획입니다. JSON 자료와 진행 토큰으로 필요한 동작을 구현할 수 있어 별도 DB의 운영·동기화가 필요하지 않았습니다. 수업에서 예시로 든 ChromaDB는 검색 방법 중 하나이며, 현재는 DB 없이 키워드로 자료를 찾습니다. **DB를 쓰지 않는 것과 임베딩 요구사항은 별개입니다.** 자료가 늘거나 플레이 기록을 영구 저장할 필요가 생기면 저장 방식을 다시 정해야 합니다.

## 실행 및 테스트

```powershell
conda activate chatbot-base
python -m pip install -r requirements.txt
python app.py
```

프로젝트 루트의 `.env`에 `OPENAI_API_KEY`와 `STORY_STATE_KEY`를 설정하고 `http://localhost:5000`을 엽니다. `.env.example`에는 공개 가능한 변수 이름과 기본값만 있습니다. 실제 키는 Git에 올리지 않습니다. `STORY_STATE_KEY`용 Fernet 키는 다음 명령으로 만듭니다.

```powershell
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

```powershell
python -m unittest discover -s tests -v
node --test tests/*.test.cjs
```

2026-11-10 로컬 검사에서 서버 테스트 62개와 화면 테스트 162개가 통과했습니다. 실제 AI 답변 품질은 별도로 확인해야 합니다. 같은 날 Vercel 공개 주소에서 새 플레이와 첫 실제 AI 대화를 확인했습니다. **모든 성별·호감도 분기·세 결말을 각각 완주하거나 30명 동시 접속을 검증한 기록은 아닙니다.** [프로듀서 시연 안내](docs/PRODUCER_TEST_GUIDE.md)에 확인 순서가 있습니다.

## 개발 중 문제와 해결

| 겪은 문제 | 적용한 해결 |
| --- | --- |
| 고정 사건 대사와 자유 대화가 따로 놀아 직전 상황에 엉뚱하게 답함 | 이미 공개된 사건 대사와 관찰 상황을 AI 입력에 연결하고 비공개 단서는 장면·단서 조건으로 제한 |
| 이전 플레이가 테스트에 겹침 | 화면을 벗어나거나 엔딩 뒤 새 시작할 때 진행 토큰을 버리고 처음부터 시작 |
| 대화 중 표정이 현재 상황과 어긋남 | 답변 생성 전 호감도를 갱신하고 표정 단서와 장면 규칙으로 인물 이미지를 고름 |
| 공개 환경에서 웹페이지 형태의 오류가 응답되어 채팅이 깨짐 | 화면에 재시도 안내를 보이고 질문을 남겨 다시 보낼 수 있게 처리 |

## 개선 결과와 검증 방법

장면의 공개 사실을 연결해 지미의 행선지, 캐런의 수색 요청, 사진 조사 같은 질문을 현재 장면에 맞춰 처리할 수 있게 했습니다. 서버 테스트는 점수 변화·정보 공개·세 결말·잘못된 토큰·모델 실패 시 상태 보존을 검사하고, 화면 테스트는 대화·조사·선택과 오류 흐름을 검사합니다. 이전 Render 배포에서는 프로듀서가 전체 시연 경로를 확인했고, 현재 Vercel 배포에서는 새 플레이와 첫 AI 대화를 확인했습니다. **응답 속도나 대사 품질의 정량 개선 수치는 아직 측정하지 않았습니다.**

## 알려진 제한과 다음 개선점

- **이미지 임베딩 유사도 미구현:** 지금은 표정 라벨과 장면 규칙을 사용하므로 과제의 답변·이미지 임베딩 비교 기준은 아직 충족하지 못합니다. 최소 구현은 이미지별 설명문과 답변을 같은 텍스트 임베딩 모델로 변환하고 코사인 유사도로 인물별 후보를 비교하는 것입니다. 이 방식에는 벡터 DB가 필요하지 않습니다.
- **발표 중 동시 접속:** Vercel 공개 주소의 기본 동작은 확인했지만 30명 동시 접속과 OpenAI API 응답 시간·사용량은 측정하지 않았습니다. 발표 전에 여러 기기에서 함께 접속해 확인합니다. 영상과 장소 이동의 지연은 [최적화 문서](docs/OPTIMIZATION.md)를 참고하세요.
- **대화 기억 범위:** 캐릭터별 최근 10번의 대화만 기억하고 영구 보존하지 않습니다.
- **화면 자료:** 실제 UI 스크린샷은 최종 제출 전 저장소에 추가해야 합니다. 날짜 전환 효과와 세 엔딩은 현재 Vercel 공개 주소에서 각각 재확인해야 합니다.

## 회고와 협업

사건·단서·결말을 서버 규칙에 두고 자유 대사를 AI에 맡기니 대화의 유연성을 유지하면서도 사건 순서와 비밀 공개 범위를 시험할 수 있었습니다. 작은 자료에는 키워드 검색과 JSON이 간단했지만, 이미지 임베딩 평가 기준과 답변 품질 검증은 별도 과제로 남았습니다.

팀장 `suyoung`은 서버·스토리, 팀원 `yejoon`은 화면·이미지를 맡아 각자 브랜치에서 작업하고 `main` 대상 PR로 합칩니다. [문서 지도](docs/README.md), [구현 현황](docs/IMPLEMENTATION_SPEC.md), [스토리](docs/STORY.md), [협업 규칙](docs/TEAM_IMPLEMENTATION.md), [Vercel 배포 안내](docs/VERCEL-GUIDE.md)를 함께 봅니다. 인물·배경 이미지는 팀의 게임 자산이며, 제작 도구의 상세 목록은 최종 발표 자료에서 확인해 추가합니다.
